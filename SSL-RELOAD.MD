# CRPV-155404 Certificate Hot Redeployment
## Задача
Реализовать механизм, который позволит администратору обновлять личные сертификаты узлов кластера без необходимости  перезапуска узлов.
## Процесс конфигурации
1. Указать параметры для настройки SSL для коннекторов узла
   Коннекторы:
    - узел <-> узел
    - узел <-> тонкий клиент
    - узел <-> REST

   Варианты настройки SSL:
    - путь до key/trust store на диске + пароль.
    - SecMan конфигурации для загрузки сертификатов из удаленного хранилища
2. Для случая конфигурации сертификатов узла через SecMan - указать за какое время до конца действия текущего сертификата узел автоматически его перезапросит и обновит.
## Процесс обновления
Сертификаты, получаемые через SecMan:
По умолчанию действия не требуются. Каждый узел перезапросит личный сертификат автоматически перед истечение срока действия текущего.
Администратор имеет возможность вызвать команду control.sh --ssl reload для ручного начала обновления.
Сертификаты, хранящиеся на диске:
- обновить файлы key store файлы на каждом узле
- вызвать команду control.sh --ssl reload
### Смена CA
На текущий момент trust store конфигурируется как путь до файла на узле.
1. Добавить новый CA в существующий trust store на всех узлах
2. Выполнить команду обновления сертификатов
3. Обновить личные сертификаты
4. Удалить устаревший CA из существующего trust store на всех узлах
5. Выполнить команду обновления сертификатов
## Механика работы
Каждый узел обновляет сертификаты независимо.
Обновленные сертификаты применяются для открытия новых соединений, существующие на момент обновления открытые соединения не затрагиваются.
control.sh --ssl reload обращается ко всем узлам кластера, обновляет сертификаты и возвращает результат.
## Валидация сертификатов перед применением
Предлагается перед применением обновленного сертификата проверять, что он является доверенным для локального trust store.
## Обработка ошибок
В случае возникновения ошибок
- control.sh --ssl reload явно возвращает администратору ошибки обновления сертификатов на участвующих узлах
- При ошибках автоматического обновления - ошибки фиксируются в логе / метриках.
  Допускается, что в случае возникновения ошибок часть узлов может иметь обновленные сертификаты, а часть - нет. В этом случае ожидается, что администратор устранит причину ошибок и вызовет команду обновления вручную / дождется следующей попытки узла обновить сертификаты автоматически.
## Мониторинг
Администратор должен иметь возможность видеть актуальную информацию по сертификатам узлах кластера через Metric API. Информация должна включать DN и Expiry Time.
Получать агрегированный отчет по всем узлам через control.sh - control.sh --ssl status
## Защита от Thundering Herd Problem
Ошибки во время автоматического обновления сертификатов не должны приводить к неограниченному кол-ву последующих повторений.
Опционально - одновременно обращение всех узлов к SecMan для обновления сертификатов может создать проблемы. Стоит предусмотреть вариант использования произвольной задержки на разных узлах.
